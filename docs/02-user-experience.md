# 02. 用户体验与回复闭环

## 1. 客户端定位

Android 是 Yance 大脑的遥控器和决策界面，不在本机独立运行完整 LLM、长期记忆或平台采集逻辑。其首要任务不是复刻各平台聊天 UI，而是把“哪些消息需要我处理、为什么、有哪些稳妥选择”呈现清楚。

## 2. 首版信息架构

### 2.1 待回复收件箱

主页跨平台聚合待回复会话，每项只展示可核验信息：

- 平台与账号；
- 联系人或群聊；
- 最后一条未回复消息；
- 未回复时长与消息数量；
- 上下文完整性；
- 是否存在明确问题、日期、价格、请求或风险信号。

“可能不满”“可能催促”等属于假设，只能作为可展开提示，不能用红色事实标签替代证据。

当没有任何 MCP 或导入数据源时，收件箱应为空，并引导用户连接数据源；这不是系统错误。

### 2.2 会话工作台

进入会话后，顶部固定展示：

- 当前人物与平台身份；
- 系统推测的关系身份，例如“直属上级”“客户”“朋友”；
- 系统建议的沟通目标，例如“澄清截止时间”“推进成交”“稳妥拒绝”；
- 本次使用的消息范围和数据来源；
- `更正身份`、`更正目标`、`查看上下文`入口。

身份与目标都允许“一次性修改”或“保存给该联系人/场景”。系统不得静默把一次选择写成长期人格偏好。

### 2.3 联系人详情

联系人长期画像由用户逐人开启。详情页包括：

- 当前 MBTI 候选与四维倾向；
- 当前关系中的行为维度；
- 重要偏好、边界和历史承诺；
- 重大事件与周/月变化；
- 支持证据摘要、反证和数据覆盖范围；
- 用户纠正、删除、重新分析和关闭长期画像的入口。

这里展示的是“此人在与用户的当前关系和已观察时间窗中的表现”，不是对其完整人格的判决。

### 2.4 连接器中心

- 查看已连接 MCP、账号、能力和状态；
- 分别启停读取、搜索、草稿、发送能力；
- 查看最近试运行、脚本版本、失败原因和权限；
- 导入用户自备 MCP；
- 可跳转独立 MCP 市场查看候选，但不会自动安装或启用。

## 3. 端到端回复流程

### 步骤 1：轻分析

新消息到达后，本地规则只做低成本处理：去重、未回复识别、明确问题/日期/价格抽取、风险信号初筛。用户打开会话时，才进行较重的 AI 分析。

### 步骤 2：分层解读

固定分成四层：

1. **字面信息**：对方明确说了什么。
2. **可能暗示**：可以并列多个解释，不强行选唯一答案。
3. **证据与反证**：引用来源消息 ID、时间和非逐字证据摘要；需要逐字核验时重新向来源 MCP 请求原文。
4. **仍未知**：明确还缺哪些信息、是否适合先澄清。

首版使用“证据较强 / 有限 / 不足”，不直接展示未经校准的百分比。

### 步骤 3：三种策略

默认提供三张有不同目标和代价的策略卡：

- **稳妥/澄清**：误判和承诺风险最低，推进速度较慢；
- **直接/推进**：行动清晰，但可能形成日期、价格或范围承诺；
- **边界/降风险**：保护用户利益与可交付性，需注意关系语气。

个人关系中可替换为“共情回应 / 直接问清 / 温和设界限”；销售中可替换为“澄清需求 / 给出方案 / 控制承诺”。三条不得只是“更礼貌、更温柔、更正式”的同义改写。

每张策略卡展示：目标、预期效果、潜在代价、新增承诺和一句示例。

### 步骤 4：草稿与一次润色

用户选择策略后获得可编辑草稿。一次润色支持：

- 更温暖、更坚定或更中性；
- 更短或保留细节；
- 不道歉、不承诺日期、不使用销售话术等禁区。

润色结果必须显示语义差异，重点标注：

- 新增或删除的事实；
- 日期、价格、交付范围等承诺变化；
- 称呼和关系姿态变化；
- 语气是否从澄清变成接受或拒绝。

用户可以采用润色、保留原稿或手动修改。首版不鼓励无限重新生成。

### 步骤 5：精确确认

确认页直接来自待执行载荷，必须显示：

- 将通过哪个平台、账号和连接器；
- 精确联系人或群聊；
- 完整最终正文和附件；
- 使用“填入但不发送”还是“确认并发送”；
- 是否能够可靠验证发送结果。

正文、联系人、附件、平台或调用方式发生任何变化，原确认立即失效。按钮应写明 `确认并发送给某人`，不能只写“继续”。

### 步骤 6：执行与回报

执行状态必须区分：

- 已填入，尚未发送；
- 已发送并验证；
- 明确未发送；
- 状态未知，需要用户检查。

状态未知时禁止自动重发。失败后保留草稿，并提供复制文本、重新定位、打开原平台或修复连接器脚本。

## 4. 关键场景规则

### 4.1 上下级

- 显示权力方向，但允许用户纠正。
- 对上级，避免把“稳妥”简单等同于无条件答应。
- 对下属，避免模糊施压和人格评价，优先明确期望、资源与下一步。
- 涉及绩效、处分、招聘、骚扰投诉或法律承诺时，提示人工审阅，不提供自动发送捷径。

### 4.2 交易与销售

- 价格、库存、房源、功能和交付日期必须来自业务 MCP 或用户确认。
- “恶意用户、同行、到手刀”只能作为风险假设；展示可核验信号和安全措施。
- 不自动拉黑、举报、取消交易、制造虚假稀缺或伪造客户案例。

### 4.3 亲密与家庭关系

- 不判断对方是否爱、嫉妒、撒谎或故意冷暴力。
- 对高不确定问题优先建议低风险追问。
- 共情版本不得自动加入用户并不认可的道歉或承诺。

## 5. 用户控制

用户可以：

- 查看并更正当前身份、目标、人物关联和画像字段；
- 控制某联系人是否建立长期画像；
- 查看使用了哪些来源和时间窗；
- 删除某字段、某时间段、某联系人画像或全部本地记忆；
- 控制是否调用云端模型；
- 启停每个 MCP 的具体能力；
- 在任何阶段退出 AI 流程并回到原平台。

## 6. 首版体验验收

- 用户能在 5 秒内找到身份更正入口。
- 用户能区分字面事实和 AI 推测。
- 三种策略的目标和代价明显不同。
- 润色新增的事实和承诺可被看见。
- 用户能在确认页准确指出平台、对象和正文。
- 任何目标不确定或状态未知的发送都能被中止。
- 测试中误发和重复发送为零。
