# 01. 产品定义

## 1. 产品要解决的问题

用户每天面对的并不只是“怎么回一句话”，而是四个叠加问题：

1. **上下文分散**：消息分布在多个平台、多个身份和多个时间阶段。
2. **关系复杂**：同一句话在领导、客户、伴侣、朋友、父母或子女之间含义不同。
3. **记忆有限**：用户很难持续记住每个人的偏好、边界、历史承诺和关系变化。
4. **表达有成本**：用户可能理解了意思，却无法在稳妥、推进、边界和关系维护之间找到合适措辞。

Yance 的价值不是代替用户社交，而是让用户在重要沟通前看见更多上下文、可能解释和选择代价。

## 2. 产品定位

Yance 是一个**本地优先的个人关系与沟通智能大脑**。回复决策副驾驶是它的第一种交付形态，经过用户反馈和真实场景验证后的可控自动回复是长期形态。

它由两部分组成：

- **大脑**：理解消息、关联人物的多个账号与身份、维护关系记忆、识别情境、学习沟通特征、生成回复策略并控制自动化范围。
- **身体**：由微信、小红书、闲鱼、钉钉、飞书等 MCP 或受控 computer-use 能力提供，负责读取聊天和平台身份、搜索、填入草稿或执行回复。

Yance 不限定 MCP 内部怎样实现，也不自行长期维护每个平台的数据采集器。连接器至少需要在授权范围内读取聊天记录、识别使用者与对方的平台身份；写入和发送属于可选能力。平台变化由连接器生态承担，大脑只依赖稳定的内部能力契约。

## 3. 目标用户

### 3.1 个人沟通

- 希望更稳妥地处理伴侣、亲友、同事与上下级关系的人。
- 容易错过隐含要求、情绪变化或历史承诺的人。
- 希望理解自己长期沟通风格和性格变化的人。

### 3.2 高频沟通与销售

- 房产中介、闲鱼卖家、顾问、自由职业者等高频处理客户消息的人。
- 需要区分真实需求、价格试探、同行询价和交易风险信号的人。
- 需要引用自有业务数据回复客户，但不希望大脑本身承担业务数据采集的人。

两类用户共享同一个大脑，但使用不同身份、目标、风险规则和业务 MCP。

## 4. 四项核心能力

### 4.1 人物、账号、身份与关系理解

- 一个真实人物可以拥有多个平台账号和平台身份；一个账号也可能存在共用或身份不明状态。
- 使用者可以同时是买家、商家、客户经营者、下属、管理者、晚辈、长辈、朋友等；当前身份由平台、账号、对象、业务和沟通目标共同决定。
- 跨平台身份关联由系统提出、用户纠正，不能只按昵称自动合并。
- 分析本人以及用户逐人开启的联系人画像。
- 以 MBTI 作为主要入口，同时记录连续行为维度和证据。
- 区分“这个人的整体人格”与“这个人在当前关系中的表现”。
- 在重大事件和周/月周期上观察变化，不用一次会话覆盖长期结论。

### 4.2 情境与隐含意图分析

- 先呈现字面事实，再列可能暗示。
- 每种暗示必须附支持证据、反证、替代解释和未知项。
- 对领导“话中有话”、客户催促、伴侣沉默等场景给出稳妥验证方式，而不是断言读心结果。

### 4.3 回复决策与表达

- 自动建议当前身份与沟通目标，用户可纠正。
- 默认提供三种有真实取舍的策略，而非同义改写。
- 允许用户选择后进行一次受约束润色，并显示承诺或事实变化。
- 早期和未获自动化授权的发送，展示真实平台、身份、对象、正文和附件，由用户逐次确认。
- 当某一身份、账号、对象类型和场景积累了足够反馈并通过验证后，用户可以主动开启范围受限、可审计、可随时暂停的自动回复。
- 自动回复越出授权范围、出现身份冲突、低置信判断、敏感关系、重要承诺、付款/删除等高风险动作或发送状态未知时，必须停止并交还用户。

### 4.4 MCP 学习与复用

- 发现用户提供的 MCP 工具。
- 通过受控样本试运行理解工具能力。
- 在用户参与纠错后，把成功调用沉淀为版本化脚本。
- 后续由本地脚本完成重复搬运、过滤和格式转换，减少模型 token。
- 出错时停下并解释，由 AI 生成最小修复并重新试运行；修复后写入或发送重新经过单次确认或自动化授权检查。

## 5. 代表性场景

### 5.1 与领导沟通

领导问：“这个事情周五能不能落下来？”

Yance 不直接断言“领导在敲打你”，而是区分：

- 字面：询问周五前能否完成。
- 可能暗示：需要对上同步进度；对当前节奏不确定；正在确认承诺。
- 已知证据：历史上是否反复追问、此前是否承诺过时间。
- 未知项：周五是否为硬截止、是否涉及第三方承诺。
- 回复选择：先澄清、直接推进、说明风险并给替代方案。

### 5.2 闲鱼交易风险

系统可以指出：资料少、评价差、反复压价、要求改变交付方式等**风险信号**，并建议面签验货、留存证据、明确到付条件；不得直接把对方定性为骗子、同行或“到手刀”。

系统同时识别使用者当前是个人买家、个人卖家还是持续经营的商家，并结合商品、价格空间、售后边界和历史承诺生成不同策略。

### 5.3 房产中介

房源数据由用户自建或第三方房源 MCP 维护。Yance 只在回答客户问题时调取经过授权的相关房源，不把“采集全国房源”变成大脑自身职责。

### 5.4 多重身份

同一用户可能同时是父亲、子女、销售、朋友、下属、管理者、闲鱼买家或商家；同一联系人也可能拥有微信、小红书、闲鱼、钉钉、飞书等多个账号，并在不同场景中呈现不同身份。身份由系统自动建议并显式展示；用户纠正后可选择“仅本次”或“对该人物、账号、关系或场景记住”。

### 5.5 高阶沟通识别与策略

长期可以探索：操控性沟通信号（包括通常被称为 PUA 的模式）、话外意图、机会信号，以及类似“三国式”多方关系和利益博弈的策略推演。输出必须说明可观察信号、证据、反证、替代解释、各方案代价和验证方式，不能把推测写成对人的定罪，也不能提供利用个人弱点进行操控的建议。

## 6. 产品原则

1. **先事实，后解释；先解释，后行动。**
2. **身份自动识别，但不能隐形。**
3. **人格是带时间和关系范围的假设，不是永久标签。**
4. **风险输出可核验信号，不给对方定罪。**
5. **连接器能力是条件，不是宣传承诺。**
6. **原文默认留在来源，Yance 不无意义地存第二份。**
7. **发送必须来自用户当下确认，或用户主动建立且仍有效的明确自动化授权。**
8. **业务知识由领域 MCP 提供，大脑只负责组合与思考。**

## 7. 首版纵向范围

首个里程碑只打通一条受控链路：

> 通用测试 MCP → 获取一个未回复会话 → 轻分析 → 用户打开 → 身份与目标校准 → 分层解读 → 三种回复策略 → 一次润色 → 精确确认 → 测试发送 → 结果回报。

首版不以真实平台覆盖量作为完成标准。微信、闲鱼、小红书属于后续连接器验收，不与大脑核心闭环绑定。

## 8. 明确非目标

- 不开发通用平台爬虫、逆向协议或反风控能力。
- 不进行没有明确身份、对象、场景和范围授权的自动回复或批量跟进。
- 不把操控性沟通信号、话外意图或机会识别输出成无证据的确定结论。
- 不提供心理诊断、忠诚判断、操控建议或雇佣筛选。
- 不把社区 MCP 包装成官方能力或安全认证。
- 不因本地运行而忽略第三方隐私、平台协议和账号风险。
- 不在首版建立复杂知识图谱、通用工作流编排平台或 MCP 商业分发体系。
