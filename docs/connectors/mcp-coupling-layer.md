# 04. MCP 耦合层

## 1. 为什么需要耦合层

MCP 能让大脑发现工具及其 JSON Schema，但不能替 Yance 回答这些问题：

- 两个名称不同的工具是不是同一种能力；
- 同一平台多个 MCP 应使用哪一个；
- 某工具是真的只读，还是会向外部系统发送数据；
- 一次试验成功后，如何安全地复用；
- 工具升级或失效后，旧脚本是否仍可信；
- 如何避免把所有工具定义和中间结果反复塞给模型。

耦合层是 Yance 的核心差异：把“模型临时调用工具”变成“可发现、可验证、可批准、可复用、可撤销的能力”。

## 2. 两级能力目录

### 2.1 原始工具目录

每个工具按以下身份记录：

`连接器 ID + 连接器版本 + MCP 协议版本 + 工具名 + schema hash`

保存工具 schema、来源、账号范围、连接状态、最近测试、风险提示和变更记录。工具名只在自身服务器内有意义，不能作为全局身份。

### 2.2 标准能力目录

规划使用可验证的内部 capability candidate；以下 ID 仅为示例，尚未冻结为正式或公开 API：

- `conversation.list`
- `conversation.read`
- `message.search`
- `contact.lookup`
- `draft.write`
- `message.send`
- `message.verify_sent`
- `domain.inventory.search`

一个标准能力可挂接多个 provider，但每个映射必须经过样本验证。协议连通不代表语义兼容。

## 3. 权限等级

| 等级 | 能力 | 默认策略 |
| --- | --- | --- |
| P0 | 发现工具、读取 schema、健康检查 | 可自动，不接触聊天正文 |
| P1 | 读取指定会话或联系人资料 | 按账号、联系人、时间窗授权 |
| P2 | 本地/远程搜索 | 区分是否出网，限制查询词和返回量 |
| P3 | 写本地草稿、标签或备注 | 展示差异，可按范围批准 |
| P4 | 发送、发布、评论、删除、举报等外部副作用 | 默认逐次确认；成熟阶段的普通回复可受独立自动化授权约束 |

MCP 的 `readOnlyHint`、`destructiveHint` 等注释只作为线索，不能作为授权事实。最终风险等级由宿主策略决定。

## 4. 同平台多 MCP 的能力级路由

用户已选择“能力级路由”，规则如下：

1. 按平台、账号、标准能力和数据范围筛选候选。
2. 过滤未授权、schema 不兼容、版本待复核或健康检查失败的 provider。
3. 依据已验证成功率、最小权限、本地性、延迟和结果完整性排序。
4. 为每种能力明确指定主 provider。
5. 同平台、同账号只允许一个写/发送 provider 激活；UI 自动化全局串行。
6. 不自动把两个 `send_message` 当成同义工具。
7. 不默认跨 provider 回退。只有效果、权限和目标完全等价且用户预先批准时，才允许受控回退。

启停粒度至少包括：连接器、账号、标准能力和具体工具。

## 5. AI 学习 MCP 的流程

### 5.1 发现

- 连接 MCP；
- 读取 server 信息和工具列表；
- 只向模型提供名称、简述、风险和少量候选；
- 确定候选后再加载完整 schema。

### 5.2 探索

AI 在最小数据和最小权限下尝试调用：

- 读取能力优先；
- 测试数据由用户指定或使用通用测试 MCP；
- 发送测试必须针对明确测试对象，并仍需逐次确认；
- 每次调用记录规范化参数、版本、结果摘要和错误。

### 5.3 用户反馈

出现参数含义、账号范围、返回字段或成功条件不清楚时，向用户提出具体问题。用户反馈可以修正能力映射，但不能隐式扩大权限。

### 5.4 候选脚本

AI 只能把**真实执行成功的调用路径**整理为候选脚本。脚本记录：

- 人类可读目的；
- 输入与输出契约；
- 标准能力及具体 provider；
- 连接器版本和 schema hash；
- 参数范围、最大条数、超时和允许的数据域；
- 外部副作用等级；
- 样本试运行记录；
- 失败和未知状态处理；
- 脱敏与日志规则。

脚本不硬编码聊天正文、凭据或固定联系人私密 ID。

### 5.5 试运行与批准

批准分成三个独立决定：

1. 允许这次试运行；
2. 允许保存候选脚本；
3. 允许脚本今后在指定范围内运行。

用户批准绑定脚本版本、hash、能力、参数范围和权限。连接器或 schema 变化后，脚本自动回到待复核状态。

### 5.6 运行

脚本只是减少重复推理，所有真实 MCP 调用仍经过权限策略与审计。早期 P4 发送逐次绑定最终载荷确认，脚本不能继承发送权。长期自动回复需要独立、可撤销且按身份/账号/对象/场景限定的授权契约，不能由一次脚本批准或单次发送确认推导出来。

## 6. 脚本状态

```text
已发现 → 探索中 → 候选 → 试运行通过 → 用户批准 → 可用
                                      │
                                      └─ 版本/schema/权限变化 → 待复核
失败 → 解释 → 最小修复 → 重新试运行 → 新版本批准
```

脚本可以停用、回滚到已知版本或删除。旧版本可用于比较，但不能复用已经失效的批准。

## 7. token 与离线化策略

1. 工具定义按需加载，不把所有 MCP schema 放进每轮 prompt。
2. 分页、过滤、去重、排序、关联和格式转换由本地脚本执行。
3. MCP 返回先按 schema 验证并裁剪，只给模型必要字段和少量样本。
4. 本地先用联系人、时间、字段和会话范围过滤聊天，再调用模型。
5. 缓存工具 schema 与能力摘要，并用版本和 hash 精确失效。
6. 复用脚本只暴露少量业务参数，内部步骤不反复经过模型。
7. 模型负责选择、解释和异常修复，不负责重复搬运数据。

研究中的 98.7% token 降幅只是 Anthropic 的代表性示例，不能作为 Yance 的性能承诺；必须在真实连接器和会话规模上测试。

## 8. AI 兜底

用户选择“解释后修复”，因此失败时固定回答：

- 发生了什么；
- 是否可能已产生外部副作用；
- 哪些对象和数据受影响；
- 已做过哪些重试；
- 修复会改变哪些参数、工具或权限；
- 是否需要重新批准。

### 8.1 可自动处理

仅在原权限范围内修正格式、字段映射或分页逻辑，并先在相同或更小样本上试运行。

### 8.2 必须停下

- 认证或权限变化；
- 工具名称/schema/版本变化；
- 需要切换到权限更高的 MCP；
- 目标联系人或发送正文变化；
- 发送超时且无法核验是否成功；
- 平台出现验证码、人脸或风控；
- 需要绕过平台限制。

状态未知时不盲目重试发送。

## 9. MCP 市场关系

Yance 可以连接独立 MCP 市场，但：

- 市场只提供发现、版本和风险元数据；
- Yance 不主动提供、打包或默认启用平台 MCP；
- 用户可以导入任意本地 MCP；
- “已列出”不等于“安全、官方或不会封号”；
- 每个连接器仍必须在本机完成能力发现、试运行和用户批准。

详见 [MCP 市场规划](mcp-marketplace.md)。

## 10. 上线阻断项

- 依据不可信 annotations 自动放行发送；
- 脚本绕过权限策略；
- 同平台同账号多个写连接器并行；
- schema 变化后继续执行旧脚本；
- 单次确认后改变联系人或正文，或自动回复越出授权身份、账号、对象、场景与内容范围；
- 状态未知时自动重发；
- 日志保存凭据或完整聊天正文；
- 沙箱外执行 AI 生成的任意代码或任意网络访问。

## 11. 关键主张来源

以下来源于 2026-08-27 复核；它们支持具体边界，不证明 Yance 已实现：

- MCP tools 规范定义工具发现、输入 schema 和 annotations；规范同时要求客户端把 annotations 视为不可信，见 [MCP Tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)。因此本规划不以 `readOnlyHint` 等注释作为授权事实。
- MCP 的授权机制与安全边界见 [MCP Authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)；Yance 的 P0—P4 是宿主侧 **PROPOSED** 策略，不是协议自带等级。
- 工具描述可能造成 tool poisoning 的风险模型见 [OWASP MCP Tool Poisoning](https://owasp.org/www-community/attacks/MCP_Tool_Poisoning)。
- 按需工具加载和本地代码处理可能减少 token 的代表性示例来自 [Anthropic: Code execution with MCP](https://www.anthropic.com/engineering/code-execution-with-mcp)；文中数字不能外推为 Yance 性能承诺。
