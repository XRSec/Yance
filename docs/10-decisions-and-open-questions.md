## 2. 已解决的表面冲突

### 2.1 多平台首发 vs 纵向闭环

“多平台首发”定义为架构、客户端和市场从一开始不绑定单平台；不意味着微信、闲鱼、小红书必须同时具备相同读写能力。第一个可验收闭环使用通用测试 MCP，真实平台逐连接器验证。

### 2.2 系统自动识别身份 vs 用户控制

系统负责预填身份和目标，但必须显式显示。用户可选择仅本次纠正或对联系人/场景记住。自动识别不是静默决定。

### 2.3 MBTI 类型为主 vs 科学可靠性

产品保留 MBTI 类型入口，但把四维连续倾向、时间范围、行为证据和不确定性作为解释基础。未经中文目标数据校准，不显示模型自报概率，也不把字母变化叫作人格突变。

### 2.4 不保存两份聊天 vs 可审计记忆

默认只保存元数据、蒸馏结果和来源 ID；逐字核验时回到来源。系统必须明确承认连接器失效后的复核能力下降。短期加密缓存或用户导入本地档案可以作为用户选择，不作为默认第二份长期副本。

### 2.5 MCP 市场 vs 不主动提供 MCP

市场是独立的发现与风险目录，不是 Yance 主应用中的连接器打包。用户自行选择、安装和导入；Yance 只负责本地能力验证和安全控制。

## 3. 暂定工程判断

这些判断由当前研究支持，但在实现前仍可调整：

1. 稳定身份、时间、来源、冲突和索引采用关系型存储；变化快的画像内容使用 JSON。
2. SQLite 是 macOS 本地首版候选，但尚未冻结。
3. 不先引入图数据库、完整事件溯源框架或向量数据库。
4. 工具身份绑定连接器 ID、版本、协议版本、工具名和 schema hash。
5. MCP 脚本是受限声明式工作流，不是 AI 任意代码。
6. P4 发送确认绑定 actor、目标、正文/附件 hash、连接器和有效期。
7. 同平台、同账号只允许一个写连接器活动。
8. 状态未知不自动重试发送。

## 4. 高优先级开放问题

### OQ-001：原文缓存策略

默认不长期复制已确定，但还需决定：

- 是否提供每个数据源独立的短期加密缓存；
- 默认缓存时长；
- 哪些关键证据允许保存脱敏原句；
- 用户导入档案如何成为本地来源；
- 删除、备份和多设备同步时如何清理。

### OQ-002：首个真实平台连接器

通用测试 MCP 完成后，优先验收微信、闲鱼还是小红书仍未决定。选择需依据：

- 用户真实场景价值；
- 是否有可接受的官方或用户自备连接器；
- 能否可靠识别消息和目标；
- 平台条款和封号风险；
- 是否能验证发送结果。

### OQ-003：MCP 市场治理

- 新仓库名称、维护者和所有权；
- 是否只收开源本地 MCP；
- 社区提交和下架流程；
- 兼容性测试基础设施；
- 安全事件通知和版本复核；
- 谁承担长期维护成本。

### OQ-004：模型组合

- 本地模型负责哪些轻分析；
- 云端模型供应商、地区、保留和训练政策；
- 何时允许用户自行配置模型；
- 不同任务的 token、延迟和质量预算；
- 云端不可用时哪些能力应直接停止，而不是使用低质量兜底。

### OQ-005：概率校准与最小样本

- 中文私聊中 MBTI 四维、情感和隐含意图如何标注；
- 本人问卷、熟人评价和行为维度如何作为参照；
- 何时证据不足必须拒答；
- 不同关系、平台、方言和年龄如何分层；
- 是否展示数字概率，还是长期保留证据强度等级。

### OQ-006：第三方画像法律基础

商业上线前需法律意见确认：联系人逐人开启、群聊有限上下文、人格与风险推断、外部模型和数据出境的合法性与告知方式。

### OQ-007：发送能力范围

首版真实连接器是否只允许“填入但不发送”，以及哪些连接器具备足够可靠的目标识别、幂等或发送回读能力。

### OQ-008：身份与 persona 规则

- 多重身份是否允许同时存在；
- 人物性格如何影响表达但不变成操控；
- 销售不同业务 persona 的用户配置方式；
- 一次性场景修正何时升级为长期偏好。
