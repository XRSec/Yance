# 07. 隐私、安全与合规边界

> 本文是产品规划，不构成法律意见。商业上线前必须由中国执业律师结合实际数据流、平台账号类型和模型供应商复核。

## 1. 默认边界

- macOS 本地保存长期记忆和连接器配置；
- Android 只获取完成当前界面所需数据；
- 原始聊天正文默认留在原平台或用户导入来源，不长期复制；
- 云端模型只接收本地裁剪、替换身份后的最小片段；
- 联系人长期画像由用户逐人开启；
- 群聊默认只分析与用户直接相关的互动；
- 每次外部发送由用户确认真实载荷；
- 不提供绕过验证码、风控、加密或平台限制的能力。

## 2. 本地优先不等于自动合规

本地运行可以减少云中继和集中泄露，但不能消除：

- 第三方聊天内容和人物画像的合法性问题；
- 平台对未授权读取、UI 自动化和自动发送的限制；
- 社区 MCP 代码、Cookie 和凭据泄露；
- 外部 LLM 的数据保留、训练、人工审阅和跨境；
- 错误人格标签、交易风险判断和职场推测造成的伤害。

产品界面和宣传必须把“本地”描述为风险降低措施，而不是合规保证。

## 3. 第三方人物与群聊

### 3.1 联系人画像

- 默认不开启长期画像；
- 用户逐人开启，并看到数据范围、用途和删除方式；
- 只显示“在与用户的互动中观察到”；
- 不生成可公开传播的羞辱性人物卡；
- 不用于雇佣、处罚、信贷、保险、教育或其他高影响决策。

### 3.2 群聊

默认可使用：用户消息、@用户、回复/引用用户及同一对话链的有限上下文。默认排除：旁观成员之间的历史、完整成员关系图、无关附件和全群人格画像。

“用户能看到”不等于产品可以持续收集、画像或传给外部模型。群聊第三方数据的合法性基础需要专项法律意见。

### 3.3 未成年人

无法可靠判断年龄时，不自动给群成员建立长期画像。一旦知道对象不满十四周岁，应停止常规人格、关系和交易风险推断，除非存在经过正式审查的监护人同意与专门保护流程。

## 4. 外部模型最小披露

发送到云端前，本地依次执行：

1. 只选择当前任务需要的消息；
2. 删除无关群成员和旁观内容；
3. 替换姓名、账号、电话、地址、订单号、公司和项目名；
4. 默认排除附件、语音、图片和文件；
5. 阻断客户名单、源代码、未公开财务、人事和商业秘密；
6. 展示供应商、区域、数据范围和保留策略；
7. 记录调用元数据，但日志不保存正文。

需要审查供应商 DPA、训练策略、零/短保留、人工审阅、子处理者和远程访问。境外模型还需评估个人信息出境要求。

## 5. MCP 与连接器安全

每个 MCP 视为独立、不完全可信的执行边界：

- 凭据按连接器隔离，不跨服务器透传；
- 模型不可读取 Cookie、token 或 Keychain 密钥；
- 工具描述、annotations、网页、聊天和返回值都可能包含提示注入；
- 工具版本和 schema hash 变化后暂停旧脚本；
- 读取、搜索、草稿、发送分别授权；
- 同平台同账号只允许一个写连接器；
- 日志脱敏，不记录完整聊天、凭据或附件内容；
- AI 生成脚本在受限执行环境中运行，不允许任意 shell、文件和网络访问。

## 6. 发送安全

发送权限不能依赖系统提示词，必须由模型上下文之外的可信界面控制。

确认页显示：

- 平台、账号、连接器；
- 联系人或群聊；
- 完整正文和附件；
- 动作类型和可逆性；
- 执行结果如何验证。

用户确认绑定这一份载荷。任何参数变化都重新确认。禁止“本会话始终允许发送”、倒计时同意和默认选中发送。

执行结果区分：已发送、未发送、状态未知。状态未知不自动重试。举报、下单、支付、删除、拉黑等高影响动作不属于普通回复发送权限，需独立设计或保持禁用。

## 7. 平台现实边界

### 微信

腾讯官方 ClawBot 是 Bot 会话通道，不等于读取个人微信已有好友和群聊。个人号数据库解密、Hook、辅助功能控制和自动化发送存在明确的平台协议与封号风险。

### 闲鱼

普通账号聊天读写主要来自社区逆向、Cookie、WebSocket 或 UI 自动化；登录、滑块、人脸、风控和封号风险不可忽略。

### 小红书

主流社区 MCP 以内容搜索、发布和评论为主，私信读取/发送尚不能视为成熟能力。UI 变化可能出现假成功。

因此 Yance 只承诺通用 MCP 接入和本地验证框架，不承诺平台能力本身。用户自备连接器也不能免除产品的风险提示和权限控制。

## 8. 人格与风险输出安全

禁止输出：

- 心理或精神疾病诊断；
- 对方在撒谎、嫉妒、操控、忠诚或爱恨的确定结论；
- “骗子、恶意用户、同行、到手刀”等无证据定性；
- 将 MBTI 或风险标签用于自动筛选、处罚或举报；
- 针对个人弱点的操控、诱导或虚假稀缺策略。

允许输出：

- 可观察行为；
- 多个可能解释；
- 支持、反证与数据缺口；
- 低风险澄清问题；
- 面签、验货、留证、限制承诺等保护措施。

## 9. 用户数据权利

用户能够：

- 查看使用的数据源和时间窗；
- 更正人物关联、身份、事实与画像；
- 关闭联系人长期画像；
- 删除单个字段、时间段、联系人或全部记忆；
- 撤销云端模型和 MCP 权限；
- 导出自己的配置、画像和决策记录；
- 看到删除后哪些来源平台数据仍不受 Yance 控制。

删除应覆盖派生结果、证据摘要、跨平台关联、缓存和待重建快照。审计需求不能成为无限保留个人数据的理由。

## 10. 商业上线前阻断项

- 未明确群聊第三方数据处理基础，却默认全量分析或长期建档；
- 未审查外部模型的数据区域、训练和保留策略；
- 未获平台授权却把逆向或 UI 自动化宣传成官方稳定能力；
- 发送链路可绕过完整预览和逐次确认；
- MCP 可接触其他连接器凭据或任意本地文件；
- 人格与风险标签用于高影响自动化决策；
- 无查看、更正、删除和撤权路径；
- 无误发、泄露、账号封禁和错误指控应急流程。

## 11. 需要正式法律意见

1. 产品公司、用户、MCP 和模型供应商各自的个人信息处理者角色；
2. 群聊第三方信息与联系人长期画像的合法性基础；
3. 人格、职场、心理状态和交易风险推断何时属于敏感个人信息或重大影响自动化决策；
4. 境外模型的数据出境路径与单独同意、合同或评估要求；
5. 微信、闲鱼、小红书各账号类型下 MCP、Accessibility、屏幕识别和 computer use 的条款边界；
6. 工作群中的劳动关系、商业秘密和客户保密；
7. 面向公众提供生成式 AI 时是否涉及算法备案、安全评估和内容治理。
