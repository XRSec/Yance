# 08. MCP 市场规划

## 1. 定位

Yance 可以建设一个独立 MCP 市场或目录仓库，帮助用户发现可用连接器，但**不在主应用中主动提供、打包或默认启用平台 MCP**。

市场的职责是披露和发现，不是替连接器背书。用户仍需在本机导入、试运行、批准和承担平台账号风险。

## 2. 与 Yance 主项目的边界

### 主项目负责

- 通用 MCP 注册与连接；
- 工具发现和 schema 校验；
- 权限分级与能力级路由；
- 试运行、脚本沉淀和本地审计；
- 用户导入任意 MCP；
- 展示连接器来源、风险和状态。

### 市场仓库负责

- 连接器目录和版本元数据；
- 官方来源、社区来源和用户自建来源标记；
- 支持的平台、账号类型和能力自述；
- 安装说明链接、许可证和维护状态；
- 已知限制、平台条款风险和安全告警；
- 兼容性与验收报告模板；
- 下架、撤回和版本风险通知。

### 不负责

- 托管用户平台 Cookie、token 或聊天数据；
- 代替用户安装和登录；
- 提供逆向协议、验证码绕过、反检测或封号规避；
- 宣称列出的连接器官方、安全、稳定或不会封号；
- 自动把不同 MCP 的同名工具合并；
- 在市场侧执行聊天读取或发送。

## 3. 条目模型

每个市场条目至少包含：

- 唯一条目 ID；
- 项目名、仓库和发布者；
- 许可证和源代码可见性；
- 官方/社区/用户自建来源；
- 支持平台与账号类型；
- 运行方式：本地 stdio、本地网络、远程服务；
- 需要的系统权限和凭据类型；
- 自报能力：读取、搜索、草稿、发送、发布等；
- Yance 独立验证过的能力和版本；
- 是否接触聊天正文、附件或第三方服务；
- 已知平台条款与封号风险；
- 最近发布、最近验证和维护状态；
- schema hash、软件供应链信息和已知安全事件；
- 失败模式、结果核验能力和是否支持幂等；
- 适用的 Yance 版本。

“自报能力”和“验证能力”必须分栏，README 宣称不能自动升级为已验证。

## 4. 信任标记

建议只使用事实型标记：

- `平台官方来源`：由平台官方发布，但仍需核对具体能力边界；
- `社区开源`：可审查源代码，不代表安全；
- `社区闭源`：无法完整审查；
- `Yance 兼容性测试通过`：仅说明指定版本通过某组契约测试；
- `写能力已验证`：说明测试对象、版本和结果核验方式；
- `高平台风险`：依赖逆向、Cookie、Hook、UI 自动化或违反条款风险较高；
- `停止维护` / `版本待复核` / `存在安全告警`。

避免使用笼统的“可信”“安全认证”或只按星数排名。

## 5. 发布与审核流程

1. 发布者提交条目和可验证来源；
2. 自动检查 manifest、许可证、版本和链接；
3. 在隔离环境连接并读取 MCP 工具目录；
4. 只用合成数据进行低风险契约测试；
5. 写能力必须使用明确测试账号和逐次确认；
6. 记录测试版本、schema hash、环境和失败；
7. 人工审阅平台能力措辞与风险披露；
8. 发布条目，但默认不自动安装；
9. 版本变化后标为待复核；
10. 出现凭据窃取、恶意代码、误发或重大条款风险时立即下架并通知。

## 6. Yance 内的安装体验

市场只提供候选信息。用户选择后：

1. 打开项目来源与风险页；
2. 用户自行完成安装或提供本地 MCP 地址；
3. Yance 展示实际工具和系统权限；
4. 默认仅启用 P0 发现；
5. 用户按能力开启读取、搜索、草稿或发送；
6. 运行样本测试；
7. 通过后建立能力映射和候选脚本；
8. 发送能力仍逐次确认。

连接器可以被注册但不暴露给模型，直到用户启用具体能力。

## 7. 多连接器治理

- 使用 Yance 生成的 connector ID 命名空间，不信任自报名称唯一性；
- 同平台同账号只允许一个写连接器处于活动状态；
- 读连接器也要按数据范围隔离；
- 不允许两个 UI 自动化连接器争抢同一个应用窗口；
- 不以自动回退掩盖主连接器故障；
- 连接器切换前展示能力差异、权限变化和脚本失效范围。

## 8. 平台条目措辞

### 微信

可以列出官方 Bot 通道与社区个人号连接器，但必须明确：官方 Bot 不等于个人微信收件箱；社区 UI/数据库方案存在兼容和封号风险。

### 闲鱼

社区 MCP 可以声称项目提供的工具，但市场不得写成官方普通账号 IM API。必须显示 Cookie、风控、人脸/滑块和版本维护风险。

### 小红书

内容检索、发布、评论与私信分开列能力。主流内容 MCP 不支持私信时，不得用“支持小红书”模糊覆盖。

## 9. 仓库决策

用户已确认市场可以通过新建仓库支持，而不是内置在 Yance。尚待决定：

- 仓库名称和所有权；
- 采用纯目录还是附带自动契约测试；
- 谁能提交和批准条目；
- 如何发布安全通告；
- 是否允许闭源远程 MCP；
- 测试基础设施和维护预算。

在这些问题解决前，首版只需保留“导入 MCP”与“打开外部市场”的产品接口，不建设完整市场运营系统。
