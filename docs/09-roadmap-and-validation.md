# 09. 路线图与验证计划

## 1. 交付原则

长期愿景支持多平台、人物时间线、回复和 MCP 市场，但交付采用**纵向闭环**，不等待四个平台达到相同能力后再验证产品。

每个里程碑必须同时回答：

- 用户能完成什么真实任务；
- 使用哪种受控数据；
- 哪些判断可以验证；
- 哪些动作需要用户确认；
- 失败时能否明确停下；
- 是否减少了 token、误判或维护成本。

不设未经验证的发布日期或平台覆盖承诺。

## 2. 里程碑

### M0：冻结规划与评测材料

**目标**：把产品边界变成可验收规则。

交付：

- 本目录规划文档；
- 术语和决策记录；
- 合成聊天样本，覆盖个人、上下级和销售；
- 通用测试 MCP 的能力契约；
- 事实/推测、身份纠正、三策略、误发和状态未知测试用例；
- 法律、平台条款和模型供应商待审清单。

完成条件：所有阻断项有明确验证方式，不再以“AI 应该懂”作为需求。

### M1：通用测试 MCP 的完整回复闭环

**目标**：不依赖真实平台，证明大脑与身体的耦合方式。

范围：

- 一个受控 MCP 提供会话列表、消息读取、草稿写入、发送和发送核验；
- Android 待回复收件箱；
- 会话身份和目标自动建议、可见纠正；
- 字面信息、可能暗示、证据/反证和未知项；
- 三种策略、草稿、一次润色与语义差异；
- 最终载荷确认；
- 已发送、未发送和状态未知回报；
- 首条成功调用沉淀为候选脚本。

明确不做：真实微信/闲鱼/小红书账号接入、长期联系人画像、MCP 市场运营。

完成条件：测试集零误发、零重复发送；确认后载荷不可改变；状态未知不重试。

### M2：本地时序记忆与本人画像

**目标**：验证“不长期复制原文”条件下的记忆价值。

范围：

- 消息来源 ID、元数据、事件、观察、证据摘要和双时间；
- 本人问卷、自评和聊天表现并列；
- MBTI 候选、四维倾向和行为维度；
- 重大事件与周/月快照；
- 用户纠正、删除和重建；
- 从来源 MCP 按需取回最小原文。

完成条件：更正不会被旧摘要覆盖；连接器不可用时明确显示无法逐字核验；删除能清除派生数据。

### M3：用户逐人开启的联系人与关系画像

**目标**：验证画像是否真正改善回复，而不是制造标签。

范围：

- 联系人逐人开启；
- 关系范围提示；
- 行为维度、MBTI 候选和时间线；
- 群聊仅使用与用户直接相关的互动；
- 跨平台身份由 AI 提议、用户确认；
- 风险假设与替代解释；
- 画像查看、编辑、删除和关闭。

完成条件：低证据时拒答；不得输出临床或确定性内心标签；用户能追溯结论范围和来源。

### M4：用户自备真实 MCP 的只读验收

**目标**：验证真实连接器接入，不把连接器问题混入发送安全。

范围：

- 用户导入 MCP；
- 原始工具目录、标准能力映射和 schema hash；
- 多 MCP 能力级路由；
- 同平台账号冲突检测；
- 只读同步、按需读取和脚本试运行；
- 平台与账号风险披露。

首批可同时调研微信、闲鱼、小红书，但逐连接器独立验收，不要求能力一致。

完成条件：文档和 UI 不把社区能力写成官方能力；版本变化能使脚本失效；凭据不进入模型和日志。

### M5：真实平台写入与发送

**目标**：只为已具备可靠目标识别和结果核验的连接器开放 P3/P4。

顺序：

1. 填入本地草稿；
2. 平台草稿或文本框填入但不发送；
3. 单次发送；
4. 发送结果核验；
5. 故障与状态未知恢复。

每个平台、账号类型和连接器版本分别验收。不能核验目标或结果的 connector 停留在只读/填入模式。

完成条件：发送前精确确认；参数冻结；未知状态不重试；无批量或无人值守发送。

### M6：独立 MCP 市场

**目标**：降低发现成本，不把维护和平台风险塞回大脑。

范围：

- 独立仓库；
- 条目 manifest、来源、许可证和风险；
- 自报能力与实测能力分栏；
- 版本兼容性和安全告警；
- 用户从市场跳转后在本机导入。

完成条件：市场不托管用户凭据或聊天；列出不等于背书；高风险连接器有明显警告和下架机制。

### M7：领域工作流

**目标**：证明“业务数据属于领域 MCP”。

候选：

- 房源 MCP + 客户回复；
- 商品/库存 MCP + 闲鱼咨询；
- 客户知识库 + 销售跟进。

Yance 只组合业务查询与沟通策略，不自行采集海量房源、商品或客户系统数据。

## 3. 验证维度

### 3.1 体验

- 身份更正入口可发现；
- 用户能区分事实和推测；
- 三种策略有真实目标差异；
- 用户能识别润色新增承诺；
- 最终消息仍表达用户真实意图；
- 用户可以跳过 AI 并回到原平台。

### 3.2 人物分析

- 本人问卷与聊天推断的对应与差异；
- 联系人低样本拒答率；
- 支持证据和反证完整率；
- MBTI 候选校准和中点识别；
- 关系/渠道混淆率；
- 短期波动误报为人格变化的比例；
- 用户纠正后是否停止重复错误。

### 3.3 记忆

- 当前与历史时间查询；
- 后续更正旧信息；
- 冲突证据共存；
- 来源不可用时的诚实降级；
- 删除后的派生数据清除；
- 快照重建是否引入无来源断言；
- 每次查询 token 和来源请求数。

### 3.4 MCP

- 工具发现和 schema 变更；
- 同名工具命名空间；
- 能力映射准确率；
- 多连接器冲突；
- 脚本试运行、批准、失效和修复；
- 凭据与日志隔离；
- 发送目标、载荷和结果核验。

### 3.5 安全

- 误发和重复发送测试门槛为零；
- 状态未知时是否停止；
- 提示注入能否诱导超权限工具；
- 云端是否只获得批准片段；
- 联系人画像是否默认关闭；
- 删除、撤权和连接器停用是否生效；
- 是否出现确定性人格、心理或恶意定性。

## 4. 评测材料

合成与经同意的匿名样本至少覆盖：

- 领导催进度但意图不明确；
- 领导明确批评；
- 朋友简短回复但实际只是忙；
- 伴侣讽刺、混合情绪和上下文缺失；
- 闲鱼反复压价、改变交付方式与正常砍价对照；
- 房产客户询问不存在或已过期房源；
- 联系人后续更正旧事实；
- 同一人在工作与私人关系中的不同风格；
- MCP schema 变化、超时、部分成功和发送状态未知；
- 恶意工具描述与聊天提示注入。

真实聊天评测必须取得明确授权并最小化保留，不用未经同意的群聊建立公开数据集。

## 5. 北极星与反指标

### 建议北极星

用户在重要对话中做出**可理解、可控且事后较少后悔的回复决定**。

### 不得单独作为北极星

- AI 建议采纳率；
- 回复速度；
- 发送消息数量；
- 联系人画像数量；
- MCP 安装数量；
- 用户对某种人格标签的认同率。

这些指标可能奖励过度迎合、过度自动化和过度画像。

## 6. 发布停止条件

任一条件成立时停止扩平台或写能力：

- 误发、重复发送或确认载荷错配；
- 高影响读心结论无证据；
- schema 变化未使旧脚本失效；
- 社区连接器被误标为官方；
- 原文或凭据进入日志或不必要的云端请求；
- 用户无法删除画像或撤销连接器权限；
- 平台出现明确封禁、重大条款变化或安全事件；
- 连接器无法稳定识别账号、联系人或发送结果。
