# 03. 系统架构

## 1. 架构目标

系统围绕一个原则设计：**macOS 上的大脑是思考与治理中心，Android 是用户决策界面，MCP 是可替换的身体。**

大脑不依赖某个具体平台工具名，也不把平台采集逻辑写进自身。它只消费经过耦合层验证的标准能力。

## 2. 逻辑组件

```text
Android 客户端
  └─ 待回复收件箱 / 会话工作台 / 联系人画像 / 最终确认
                 │ 局域网请求与结果
                 ▼
macOS 本地大脑
  ├─ 客户端会话与权限入口
  ├─ 待回复与轻分析引擎
  ├─ 情境 / 身份 / 目标识别
  ├─ 人物与关系分析
  ├─ 时序记忆与证据检索
  ├─ 回复策略与润色编排
  ├─ 可信确认与执行控制
  └─ MCP 耦合层
       ├─ 连接器注册与能力目录
       ├─ 能力级路由与冲突控制
       ├─ 探索、试运行与脚本库
       ├─ 权限策略与审计
       └─ MCP Clients ── 用户提供的平台/业务 MCP
```

## 3. 各层职责

### 3.1 Android 客户端

负责展示和接收用户决定：

- 待回复会话；
- 分层解读与三种策略；
- 身份、目标和画像纠正；
- 草稿编辑与一次润色选择；
- 最终发送确认；
- 连接器能力启停。

Android 不成为第二套长期记忆或第二个模型运行中心。可保留必要的短期界面缓存，但不作为事实源。

### 3.2 客户端会话与权限入口

- 只接受已配对设备的局域网访问；
- 把“浏览/分析”和“请求发送”分开授权；
- 为每次发送生成绑定真实载荷的确认记录；
- 不把模型生成的“用户应该同意”当作用户授权。

### 3.3 轻分析与待回复引擎

- 从连接器事件或按需同步中识别新增消息；
- 维护消息元数据、未回复状态和会话水位；
- 使用本地低成本规则提取明确问题、日期、价格和任务信号；
- 不在后台对每条消息进行完整人格分析。

### 3.4 情境、身份与目标识别

产生可修改假设：

- 用户当前身份：下属、管理者、销售、父亲、朋友等；
- 对方身份与关系；
- 当前沟通目标；
- 风险类型与上下文完整性。

所有结果都必须展示给用户，用户明确纠正后才可长期记住。

### 3.5 人物与关系分析

- 本人画像可结合问卷、自评、历史聊天和用户修正；
- 联系人画像只在用户逐人开启后维护；
- MBTI 是主要入口，行为维度和时间范围是解释基础；
- 群聊默认只使用与用户直接相关的互动；
- 不输出临床诊断、忠诚判断或确定性内心动机。

### 3.6 时序记忆与证据检索

本地大脑长期保存：

- 平台、账号、会话、参与者和消息来源 ID；
- 发送时间、发送方、接收方、回复关系等元数据；
- 事件、事实/观察、证据摘要、冲突和更正；
- 周/月及重大事件画像快照；
- 用户修正和处理版本。

默认不长期复制平台聊天正文。需要逐字核验时，按来源 ID 重新向连接器请求；连接器不可用时，系统必须承认无法逐字复核。

### 3.7 回复编排

- 根据当前问题构造最小证据包；
- 区分事实、推测和未知；
- 生成三个有不同代价的策略；
- 根据用户选择生成草稿；
- 一次润色并比较语义差异；
- 把最终载荷交给可信确认层，而不是直接调用发送工具。

### 3.8 MCP 耦合层

负责将不稳定、不同名的工具转成内部标准能力。详细规则见 [MCP 耦合层](../connectors/mcp-coupling-layer.md)。

## 4. 数据所有权与事实源

| 数据 | 默认事实源 | Yance 长期保存 |
| --- | --- | --- |
| 原始聊天正文 | 原平台、用户导入档案或用户指定来源 | 默认否 |
| 消息身份与时间 | 平台来源 + 本地同步水位 | 是 |
| 事实、事件、人物观察 | 本地蒸馏 | 是，含来源 ID 与不确定性 |
| 用户纠正 | 本地大脑 | 是，优先级高于模型推断 |
| MCP 工具与 schema | 当前 MCP + 本地版本缓存 | 是，按版本/hash 失效 |
| 最终发送载荷 | 用户确认记录 | 正文默认只留 hash/摘要；具体保留待定 |
| Android 界面状态 | macOS 会话状态 | 仅短期同步 |

用户手动导入完整聊天档案时，该档案可以成为用户指定的本地来源，而不是再复制进多套数据库。

## 5. 模型调用边界

### 5.1 本地处理优先

本地完成：去重、时间过滤、元数据聚合、未回复判断、能力路由、权限判断、脚本执行、结构化检索和敏感字段替换。

### 5.2 云端按需

只有较重的语义分析、策略生成或用户选择的高级模型需要云端时，才发送最小必要片段。调用前应能说明：

- 使用哪个模型与区域；
- 发送哪些字段和多少条消息；
- 是否包含第三方敏感内容；
- 供应商保留与训练策略。

云端模型不获得完整本地数据库、MCP 凭据或发送权限。

## 6. 无连接器状态

大脑可以独立启动，但没有任何数据源时：

- Android 收件箱为空；
- 人物画像只包含用户主动填写或问卷数据；
- 连接器中心引导用户导入 MCP 或本地聊天档案；
- 系统不伪造演示联系人，也不把“暂无数据”当故障。

## 7. 关键隔离

1. **读取与发送隔离**：能读不等于能写，能写草稿不等于能发送。
2. **模型与凭据隔离**：模型不接触平台 Cookie、token 或 Keychain 密钥。
3. **连接器互相隔离**：每个 MCP 是独立信任域，不共享凭据或完整上下文。
4. **分析与授权隔离**：模型建议不能生成用户授权。
5. **原文与蒸馏隔离**：来源正文不因生成画像而默认复制到本地长期库。
6. **身份与人格隔离**：用户在某次会话中的角色不等于其固定人格。

## 8. 架构停止条件

出现以下情况时不得继续自动执行：

- MCP schema 或版本变化，原脚本尚未复核；
- 同一平台/账号存在多个写连接器争用；
- 连接器无法确认目标联系人；
- 云端调用需要超出用户允许的数据范围；
- 人物或关系证据不足，却要做高影响结论；
- 发送后状态未知；
- 平台要求验证码、人脸或风控验证；
- 用户撤销权限、关闭联系人画像或删除数据。
