## 一句话定义

Yance 是运行在 macOS 本地主机上的“社交沟通大脑”：它不自行维护微信、闲鱼、小红书等平台采集器，而是通过 MCP 耦合层接入用户提供的连接器，理解人物、关系、情境与长期变化，向 Android 端提供可解释的回复策略；任何真实发送都由用户逐次确认。

## 核心判断

1. **大脑与身体分离**：Yance 负责理解、记忆、规划与安全控制；MCP 负责平台数据和动作。
2. **连接器不是产品承诺**：能否读取、搜索或发送，取决于用户接入并通过验证的 MCP。Yance 不承诺三方平台开箱即用。
3. **AI 与 MCP 之间需要耦合层**：发现工具只是第一步，还需要能力归一、冲突处理、权限控制、试运行、脚本沉淀、审计和故障修复。
4. **人物分析是动态假设**：MBTI 是主要入口，但必须同时展示行为维度、证据、反证、适用时间段和不确定性。
5. **回复是人机协作，不是自动代聊**：AI 提供分层解读、三种策略和一次润色；用户决定目标、最终措辞和是否发送。
6. **本地优先但不重复保存聊天正文**：默认由原平台或用户导入的数据源保存原文；Yance 长期保存消息元数据、蒸馏结果和来源引用。是否启用短期加密缓存由用户另行决定。

## 已确认的产品方向

- 同时覆盖个人关系、上下级沟通与销售场景，但采用纵向闭环逐步交付。
- 长期愿景支持微信、闲鱼、小红书和通用 MCP。
- 首个验收闭环使用受控的通用测试 MCP，而不是先承诺真实平台能力。
- Android 首页采用“待回复收件箱”。
- 身份由系统自动识别，但必须可见、可纠正，并记住用户的明确修正。
- 沟通目标由 AI 建议、用户确认。
- 隐含意图采用“字面含义—可能暗示—证据/反证—未知项”的分层推测。
- 默认提供三种有真实取舍的回复策略。
- 联系人长期画像由用户逐人开启；群聊默认只分析与用户直接相关的互动。
- 跨平台人物关联由 AI 提议、用户确认。
- 云端 AI 只按需接收最小必要片段；原始数据不经云中继。
- 每次发送都展示真实目标和完整载荷，并由用户明确确认。
- MCP 市场可以建设为独立仓库或独立目录服务，但 Yance 不主动内置或提供平台 MCP。

## 术语

- **大脑**：Yance 在 macOS 上的本地分析、记忆、规划与权限控制系统。
- **身体**：能够读取平台数据或执行动作的外部连接器。
- **MCP 耦合层**：位于 AI 与 MCP 之间，将不稳定工具转化为受控能力和可复用脚本的层。
- **能力**：与具体工具名无关的业务动作，如读取会话、搜索联系人、写入草稿、发送消息。
- **脚本**：AI 在试运行成功后沉淀的、绑定工具版本和权限范围的可审计工作流；不是任意代码执行。
- **画像**：基于指定关系、渠道和时间窗形成的可修改假设，不是对一个人的永久定论。
- **来源正文**：保留在原平台、用户导入档案或用户指定数据源中的原始聊天文本。
- **蒸馏**：从有限消息窗口中提取事件、行为观察、人物倾向和关系变化，并保留来源引用的过程。

## 不应出现在规划中的承诺

- 安装 Yance 后即可读取或发送所有微信、闲鱼、小红书消息。
- AI 能准确读懂领导、伴侣或客户的真实内心。
- MBTI 或情感标签是确定、永久、可用于筛选人的事实。
- 本地运行自动等于合规、安全或不会封号。
- MCP 描述、工具注释或调用成功返回天然可信。
- 用户曾经批准过一次发送，系统以后就可以自动发送。
